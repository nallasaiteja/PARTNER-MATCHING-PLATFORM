# Partner Matching Platform — Production Deployment Guide

> **Document Version:** 1.0.0  
> **Classification:** Confidential / DevOps & Deployment Guide  
> **Target Environments:** Cloud PaaS (Render, AWS, DigitalOcean, Railway) + Supabase Managed PostgreSQL

---

## 1. Prerequisites & System Requirements

### 1.1 Server Infrastructure
- **Operating System:** Ubuntu 22.04 LTS (recommended) or any modern Linux/Unix container runtime.
- **Node.js Runtime:** Node.js v18.x LTS or v20.x LTS.
- **Package Manager:** `npm` (v9+) or `pnpm` (v8+).
- **Process Manager:** `pm2` (v5+) or Docker / Container Orchestrator.
- **Reverse Proxy / SSL:** Nginx or Cloudflare with TLS 1.2 / 1.3 certificates.

### 1.2 Database Infrastructure
- **Managed PostgreSQL:** Supabase PostgreSQL 15+.
- **Supavisor Connection Pooler:** Active on Port `6543` (transaction mode).
- **Direct Connection:** Active on Port `5432` for administrative schema migrations.

## 3. Database Migration & Initialization

Execute database schema sync and Prisma client generation from the `backend/` directory:

```bash
cd backend

# Install dependencies
npm ci

# Generate type-safe Prisma client
npx prisma generate

# Synchronize schema definitions with Supabase PostgreSQL
npx prisma db push
```

> **Warning:** Never run `prisma migrate reset` in a production environment as this drops existing data. Always use `prisma db push` or non-destructive migrations.

## 4. Supabase Storage & Security Policy Configuration

1. In the **Supabase Dashboard**, navigate to **Storage -> Buckets**.
2. Verify or create the following buckets:
   - `member-photos` (Public: enabled for optimized profile image streaming).
   - `member-documents` (Private: disabled public access; access requires short-lived signed URLs generated by the backend).
   - `resumes` (Private: candidate job application resumes).
3. Ensure Row-Level Security (RLS) is enabled on all sensitive application tables:
   ```sql
   ALTER TABLE "User" ENABLE ROW LEVEL SECURITY;
   ALTER TABLE "MemberProfile" ENABLE ROW LEVEL SECURITY;
   ALTER TABLE "AuditLog" ENABLE ROW LEVEL SECURITY;
   ```

## 5. Reverse Proxy & HTTPS / TLS Configuration (Nginx)

The application code enforces HSTS, frame-ancestor protections, and HTTPS redirection. Deploy Nginx as the front-facing TLS termination proxy:

```nginx
server {
    listen 80;
    server_name api.matrimony.yourdomain.com matrimony.yourdomain.com;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl http2;
    server_name api.matrimony.yourdomain.com;

    ssl_certificate /etc/letsencrypt/live/api.matrimony.yourdomain.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/api.matrimony.yourdomain.com/privkey.pem;

    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_ciphers HIGH:!aNULL:!MD5;
    ssl_prefer_server_ciphers on;

    # Pass client IP to backend for audit logging
    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto https;
        proxy_read_timeout 90;
    }
}
```

## 6. Automated Daily Backups & 30-Day Retention Setup

The platform includes an automated backup script `backend/scripts/backup-database.ts` that enforces a minimum 30-day retention window.

### 6.1 Running Backup Manually
```bash
cd backend
npm run db:backup
```

### 6.2 Scheduling Automated Daily Backups via Cron
Add a daily cron job on the production server (scheduled at 02:00 AM UTC):

```bash
crontab -e
```
Add the entry:
```cron
0 2 * * * cd /var/www/matrimony/backend && /usr/bin/npm run db:backup >> /var/log/matrimony-backup.log 2>&1
```

### 6.3 Supabase Native Point-in-Time Recovery (PITR)
On the Supabase Pro/Team tier:
1. Navigate to **Project Settings -> Database -> Backups**.
2. Verify that **Daily Automated Backups** or **Point-in-Time Recovery (PITR)** is toggled **ON**.
3. Confirm that retention is set to 30 days.

## 8. Rollback & Disaster Recovery Procedures

1. **Service Incident / Application Crash:**
   - Review PM2 logs: `pm2 logs matrimony-api`.
   - Rollback to previous deployment git commit: `git checkout <previous-tag> && npm run build && pm2 restart matrimony-api`.
2. **Database Data Recovery:**
   - In Supabase Dashboard: Navigate to **Backups -> Point-in-Time Recovery**, select the target recovery timestamp, and restore to a target branch.
   - For file dumps: Execute `pg_restore -h <db_host> -U postgres -d postgres < /var/backups/matrimony/db_backup_[TIMESTAMP].dump`.
